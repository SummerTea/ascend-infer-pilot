# 06 · J0 定焦（Triage）：瓶颈收窄与约束点定位（昇腾版）

> **定位**：J0 = **先收窄再冻结**。在 J1 之前用 ≤3 轮的粗口径测量，把「推理短板 / 约束点」收窄成一个焦点，产出**定位卡**（`01-triage.md`：一个瓶颈/约束点 + 证据 + 占比 + 候选阶梯 + 收益上限）；**无定位卡不得进入 J1 / J4 / J5**。

## 1. J0 定焦总览（为什么先收窄）

- **一句定位**：J0 = **先收窄再冻结**；产出是**定位卡**（一个瓶颈/约束点 + 证据 + 占比 + 候选阶梯 + 收益上限）。
- **阶段链**：`J0 定焦` → J1 → J1.5 → J2 → J3 → J4 → J5 → J6。
- **台账顺序（8 个顺序步）**：`00-probe → 01-triage → 02-scope → 03-baseline-ledger → 04-freeze-and-gate → 05-bootstrap → loop: iterations/it-NNN → summary.md`（第 9 项 `state.json` 随 loop 逐轮维护），落 `workspace/<scenario-id>/ledger/`（不入库，规范见 [docs/05 §3](05-case-library-and-ledger.md)）。
- **为什么先定焦**：J1 的四输入（硬件 / 模型特征向量 / 负载 / SLO）在**无焦点**时无法填——SLO 的可达性依据「可达上限」必须先量出来；先定焦后，J1/J1.5/J2 只需围绕**这一个焦点**做，J1.5 的 gap 清单也只对焦点相关组件列，范围立刻收窄，杜绝「入口即全局普查」。
- **J0 明确不做**：不做全量算子盘点、不列完整账本、不写 J2 全量双约束账本、不对比所有候选阶梯——只回答「短板在哪一段 → 哪一类 → 哪个落点」，其余留给 J1 之后围绕焦点做。
- **前置**：J0 需要机器档案与前置齐备性（见 `workspace/<scenario-id>/ledger/00-probe.md`）——**跑不了测量就没有 J0**；机器档案缺失、容器未就绪、`msprof` 最小探针跑不出数据，先回 `00-probe` 补齐，不进 R1。

## 2. R1 定阶段（哪一段是热点）

- **问什么**：瓶颈在 **prefill / decode / 通信 / 调度（下发）** 哪一段？（**加载**属冷启动、不计入稳态占比窗口；确属加载瓶颈 → 直接转 §8 容量 / IO 视角）
- **手段（命令级）**：
  - 端到端粗采：`msprof --output=<dir> --application="python3 run_serve_or_step.py"`（timeline 轨道占比；先 `source set_env.sh`，采集细节见 [诊断 SOP §msprof 采集与归因实操](02-ascend-diagnosis-sop.md)）
  - 引擎指标：`vllm:time_to_first_token_seconds` vs `vllm:token_latency`（TTFT vs TPOT 占比，秒级定性）
  - 开环压测：`vllm bench serve --request-rate <固定到达率>`（固定到达率，**先预热到稳态**再统计）
- **纪律**：预热到稳态；报**中位数与 P95/P99**（不报单次最优）；只信 `msprof`（[AGENTS.md §4](../AGENTS.md)）。
- **占比口径**：阶段占比按端到端关键路径（稳态窗口）计，`占比 = 该段累计耗时 / 窗口总耗时`，从 timeline 轨道直接读；引擎指标（TTFT / TPOT）只做交叉验证，不做占比依据。**阶段占比合计须 ≥ 90%**；不足即存在未归因 bucket，按 §7「信息不足」处理（先补齐归因再判热点）。
- **出口**：**阶段占比排序**（例 `decode 68% / prefill 20% / 通信 12%`），**锁 top-1**（或 top-2，若能证明二者可并行处理）。
- **失败转哪**：占比**均衡且都接近本机上限** → 转 **§8 约束点分支**；**有明显 top-1 但占比 < 20%**（分布型热点）→ 同样转 **§8**；无负载 / 无 SLO → **§7 熔断（信息不足）**。

## 3. R2 定类别（算 / 读 / 发 / 传）

- **问什么**：锁定的那段属于 **算得太慢 / 读得太慢 / 发得太慢 / 传得太慢** 哪一类？
- **手段**：`AI` vs `B*` 的**粗口径** roofline（见 §5）+ msprof **五表**（Kernel / 通信重叠 / 融合模式 / 下发效率 / 内存效率，过滤 ≥1%）+ **直接复用 [诊断 SOP §3 四大瓶颈逐节定位](02-ascend-diagnosis-sop.md) 的既有判据（引用，不另造）**：
  - **算**：Prefill `MFU_eff < 35%` 报警（阈值须随本机 `P_eff` 标定重定，**禁移植 NVIDIA 数值**）；先排除节流（`npu-smi` 功耗/温度/频率）
  - **读**：单算子有效带宽 ≥75%~90% 且计算单元利用率极低；**再用 `实际字节 / bytes_min` 细分**——`≈1` → 真带宽极限（量化破局）、显著 `>1` → 算子未融合的冗余 HBM 往返（垂直融合）；**两者同属「读得太慢」**，不得因 `>1` 判为不满足本类
  - **发**：**Bubble Ratio > 20%** 为严重（优秀 <5%）；前提是**负载打满**
  - **传**：唯一判据是**暴露时间** `exposed_comm = comm_time − overlapped_time` 在 step 关键路径的占比（"通信总耗时 >25% 但被计算覆盖"**不算**瓶颈）
- **出口**：**一个瓶颈类别 + 关键指标证据**（写明指标名与值，如 `MFU_eff = 28%` / `Bubble Ratio = 31%`）。
- **失败转哪**：两类都像 → 取**占比更大**者，并在定位卡记「次候选」；都不到阈值 → **§7 熔断（无显著瓶颈）**。

## 4. R3 定落点与手段（哪个器件 / 候选阶梯 / 收益上限）

- **问什么**：具体在**哪个算子 / 通信原语 / 调度环节**？候选手段映射到**五阶梯**（1 配置与编排调优 / 2 已有成熟后端切换 / 3 Out-of-tree 插件扩展 / 4 专用 Kernel 移植与开发 / 5 底层引擎内核重写与 Fork，排序见 [docs/01 §5](01-pipeline-and-ledger.md)）？**收益上限**多少？
- **手段**：
  - 算子：`msprof op --output=<dir> --application="python3 benchmark_op.py"` 取 Top-N（**≥1% 占比过滤**），低于 1% 不进归因
  - 调度：timeline 按「NPU busy 并集」算 **Bubble** 并锚定 wait-anchor（等同步 / 等下发 / 等通信，口径见 [诊断 SOP §msprof 采集与归因实操](02-ascend-diagnosis-sop.md)）
  - 通信：`hccl_test` busbw 与同拓扑基线比 + `exposed_comm` 占比 + **快慢卡三分类**（Host 下发慢 / 计算慢 / 通信慢，见 [诊断 SOP §HCCL 与通信排障实操](02-ascend-diagnosis-sop.md)）
  - 算子级微基准一律 `msprof op`（**禁** `time.time()` / `torch.npu.Event` / `do_bench`，[诊断 SOP §2.1](02-ascend-diagnosis-sop.md)）
- **收益上限的算法**（"值不值得做"的依据）：以**该落点占端到端比例**为上限锚——某落点占端到端 18%，把它优化到理论最优**最多回收 ~18%**（占比 = 可回收上限，不计落点自身已实现的部分）；有 SLO 时再与目标 gap 比较：`可回收上限 ≥ gap` 才值得做。
- **出口**：**定位卡**（字段见 §9），含落点、候选阶梯、收益上限与证据。

## 5. 粗口径 vs 精口径账本

- **粗口径（J0 内）**：`P_eff ≈ α · P_peak`、`BW_eff ≈ β · BW_peak`，建议初值 **α≈0.65 / β≈0.70**（可配，取值记录在定位卡）；**只用于判「算还是读」**；**明确禁止用于 J6 门禁或验收阈值**（粗口径不得用于 J6 门禁——门禁分母必须是本机实测，见 [门禁规则](../gates/README.md) 五）。
- **精口径（原 J2，`03-baseline-ledger.md`）**：定焦后**只对焦点相关维度**做本机微基准校准——大 GEMM 得 `P_eff`、大 copy/STREAM 得 `BW_eff`（命令见 [docs/01 §4](01-pipeline-and-ledger.md)），**替换粗口径值**进 J2 账本。
- **共享校准**：`workspace/_shared/calibration.md` 已有同 `<模型>@<硬件>` 精口径值时直接引用（不算粗口径），无需在 J0 重测；换 CANN / torch_npu / 芯片版本必须复测。
- **判据**：`B* = P_eff / BW_eff`；`AI > B*` → 算力受限，`AI < B*` → 访存受限；判据须与**当前精度**一致（换精度 `B*` 变，重判）。

## 6. 硬出口四条件（进 J1/J4/J5 的闸门）

进 J1/J4/J5 必须**同时满足**（否则**不得动手**，回 §2/§3 换手段）：

1. 候选瓶颈**占端到端 ≥ 20%**（**逐项计**；仅当二者可并行处理时才可合计；默认 20%，最终取值写在定位卡「结论」行以便复算）
2. 有 **`msprof` / `msprof op` 证据**（禁"我猜"；每条结论须可指到命令与产物路径）
3. 有**明确的候选阶梯**（1~5 之一，并说明为何更高 ROI 的阶梯不适用）
4. 预期**收益上限 ≥ 目标 gap 的 50%**（**仅在有 SLO / gap 时生效**；无 SLO 时本条跳过，改由「条件 1 占比」+「定位卡置信度 ≥ 中」把关）

并明确一句：**无定位卡不得进入 J1 / J4 / J5**（硬约束，与 `AGENTS.md` 一致）。

> **回边**：四条件任一不满足 → **不得动手**，回 §2/§3 换手段（换测量口径 / 换负载 profile / 换落点假设），并把「本轮学到什么 + 下轮换什么」记入定位卡「熔断轮次记录」。

## 7. 熔断与升级（3 轮上限 + 四类原因）

- **时间盒**：R1~R3 合计 **≤ 3 轮**；每轮在定位卡「熔断轮次记录」写「本轮学到什么 + 下轮换什么手段」；**超限 → 升级给人**（写清"缺什么、要谁给"）。
- **四类原因 + 固定动作**：

| 原因 | 判定信号 | 固定动作 |
|---|---|---|
| 信息不足 | 无负载模型 / 无 SLO / 无权重或数据集 | 向持卡人索取；或**缩小任务**（先定一个 profile，如单请求 decode） |
| 权限不足 | profiling / HCCL / 锁频 无权限，采集拿不到数据 | 给出**所需命令与权限清单**，请人开通（不要反复重试） |
| **无显著瓶颈** | 各段占比均衡且均接近本机上限；**或 top-1 占比 < 20%（分布型热点）** | **转 §8 约束点分支**；若阶段占比合计 < 90%（有未归因 bucket）→ 按「信息不足」处理 |
| 目标不可达 | 粗口径账本已证明物理不可达 | 回人**重谈 SLO**（对应 J2 回边） |

## 8. 约束点分支（容量 / 并行 / 精度 / 调度）

四类，每类给：**判定信号 / 定位视角 / 候选手段**：

1. **容量约束**：显存或 KV 容量打满 → 并发上不去（`BW_util`/`MFU_eff` 都不高）。视角：显存容量账本（权重 / KV / 系统余量，公式见 [docs/01 §4](01-pipeline-and-ledger.md)）。手段：KV 量化 / 分层、Paged / 块大小、并发与 batch 上限、PD 分离。
2. **并行约束**：TP/EP 切分与拓扑不匹配（单机 HCCS vs 跨机 RoCE）、专家倾斜。视角：拓扑（`npu-smi info -t topo`）+ `hccl_test` 同拓扑基线 + 路由统计。手段：调整 TP/EP、EPLB / 专家均衡、DeepEP→CAM。
3. **精度约束**：只有量化才达标，但精度门禁不过。视角：L1/L2/L3 定级路径 + 下游任务误差预算（见 [门禁规则](../gates/README.md) 二）。手段：更细粒度量化、混合精度、KV 精度分级。
4. **调度约束**：请求级 / 前缀级调度不当（前缀亲和缺失、PD 未分离）。视角：TTFT/TPOT 分位 + 命中率。手段：前缀感知路由 / 亲和、PD 分离、图捕获分桶。

- 一句总括：**约束点不是"哪个算子慢"，而是"哪个资源先到顶"** —— 这类问题测得再细也找不到热点。

## 9. 定位卡（`01-triage.md`）字段规范

字段（逐字使用下列字段名，落 `workspace/<scenario-id>/ledger/01-triage.md`）：

| 字段 | 内容 |
|---|---|
| **阶段** | 锁定的阶段（prefill / decode / 通信 / 调度；加载属冷启动，见 §2） |
| **类别** | 算 / 读 / 发 / 传（或 §8 约束点四类之一） |
| **证据** | `msprof` 命令 + 指标值（如 `MFU_eff = 28%`，附产物路径） |
| **占端到端比** | 落点占端到端百分比（四条件 1 的依据） |
| **候选阶梯** | 1~5 之一 + 为何更高 ROI 阶梯不适用 |
| **收益上限** | 按 §4 算法给出可回收上限（%） |
| **置信度** | 高 / 中 / 低（低置信度不得进 J1） |
| **未定项** | 尚未确认的事项与需要的输入 |

另加：**次候选**（可选）；**熔断轮次记录**（每轮"学到什么 + 下轮换什么"）；**结论：可否进 J1/J4/J5（四条件逐条 ✅/❌）**。
