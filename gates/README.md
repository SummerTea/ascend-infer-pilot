# gates/ —— 双轨门禁规则与所有权（昇腾版）

> 本目录是门禁的**规则与口径声明**，不含门禁脚本本体。门禁脚本 / 基线 / 容差由架构师持有并单独落仓，Agent 只读。规则对齐主文档 J6 双轨门禁（轨道 A 正确性与精度、轨道 B 性能与稳定性）。

## 一、门禁所有权规则

1. **所有权分离**：门禁脚本、基线数据、容差阈值由架构师持有并对 Agent **只读**，落在 **Agent 无写权限的独立仓或受保护分支**；CI 仅从该处拉取。任务书中显式声明该路径禁写。
2. **独立执行**：门禁在干净容器 / CI 中运行，输入为冻结环境（CANN / torch_npu / PyTorch / 驱动 / 引擎 commit 快照）与固定的权重 / 数据集。
3. **一键复现**：交付必须附从零复现的完整命令与版本信息；「换台机器跑不出同样结果」即视为未通过。
4. **Agent 职责边界**：Agent 只提交实现与自测（`test_op.py` / `benchmark_op.py`），不得修改门禁脚本、基线或阈值。
5. 五不准红线第 5 条（测试套件人为弱化）只是事后审查，不能替代上述机制。
6. **版本快照**：门禁运行环境（CANN / torch_npu / 引擎 commit / 权重 / 数据集）与门禁结果作为**过程留痕**归档到 `workspace/<scenario-id>/ledger/`（不入库），供复现与复盘；**入库形态 = 条目 md 的第 5 节**（规范见 [docs/05](../docs/05-case-library-and-ledger.md)）。

## 二、数值语义容差表（4 档）

| 档位 | 语义 | 适用路径 | 判据 | 禁止用法 |
| :--- | :--- | :--- | :--- | :--- |
| **L1 逐位一致** | 输出与 golden 完全一致 | 数学等价路径（融合 / 重排 / 平替 Kernel）的最低档 | 同配置多次重跑逐位比对（含跨配置 md5 级抽查） | 禁止用「100% 逐字吻合」做硬门禁——bf16 下归约顺序一变 logits 即抖 ~1e-3，长生成必现个别 top-1 翻转，该门禁不可稳定通过 |
| **L2 数值门** | 余弦相似度 + 最大/相对误差**双指标并用** | 单算子级 / 引擎等价替换（基准 dtype：bf16 / fp16 / fp8） | `torch.testing.assert_close(actual, expect, rtol=..., atol=...)`，按 dtype 理论浮点容差设定；余弦对整体幅度不敏感，**不可单用** | 禁止单用余弦或单用均值指标；禁止用平均相对偏差做 logprob 指标（logp 接近 0 时分母爆炸） |
| **L3 有损门** | 下游任务误差预算制 | 量化 / KV 压缩等有损路径 | 用 evalscope 等评测 MMLU / GSM8K，阈值按**任务与评测噪声**校准（多次运行 + 置信区间） | 禁止「零误差」标准；禁止「综合得分掉点 ≤ 1.0%」这类跨任务一刀切 |
| **探索态-验收态协议** | 探索态可快速迭代，**验收态才允许入库** | 全路径 | 同窗 A/B 协议（同并行度 / 同 batch / 同 shape / 同图分桶）对比；验收态须附完整复现链 | 禁止以探索态数据入库；禁止「改造前 vs 改造后」A/B 作正确性锚点（只作回归项，正确性必须锚定独立 golden） |

> 正确性锚点：L1/L2 的 golden 是独立参考实现（transformers eager / 官方实现，fp32/fp64），不是改造前的引擎输出——改造前可能本来就是错的（尤其新模型接入，见 J1.5）。

> **L2/L3 阈值设定法**：先测「正确实现相对 golden 的偏差噪声底」（跨不同归约顺序 / batch 形状多次比对，取翻转率与 `mean |Δlogp|` 的离散度），再按 dtype 理论浮点容差设定 `rtol` / `atol`；改造后须落在噪声底内。L3 的任务阈值按评测噪声校准（多次运行 + 置信区间），不用跨任务一刀切。

## 三、轨道 A：正确性与精度门禁清单

| 检查项 | 判据 | 证据产物 |
| :--- | :--- | :--- |
| 单算子正确性 | 余弦 + 最大/相对误差双指标（L2 档） | `test_op.py` 输出 |
| 整模级正确性 | 锚定 golden，比对 token 序列与 logprob（`mean |Δlogp|` / top-k KL） | 比对报告 |
| 采样分布 | `temperature > 0` 时 KL / 采样一致率验证 | 抽样报告 |
| 有损路径 | 下游任务误差预算（L3 档） | evalscope 评测 MMLU / GSM8K 报告 |

## 四、轨道 B：性能与系统稳定性门禁清单

| 检查项 | 判据 | 证据产物 |
| :--- | :--- | :--- |
| 收益达标 | 相对基线 ≥ 预估收益 80%（禁止 J2 物理下界作分母） | `benchmark_op.py` / 压测报告 |
| 开环 Goodput | 固定到达率，P95 TTFT / TPOT 达标率 | 压测报告（声明到达模型与统计窗口） |
| 边界与混合负载 | Batch=1 与最大 Batch；极端短 / 长 Prompt；prefill / decode 混跑 | 测试记录 |
| 回归抽检 | ≥ 1 个 Dense + 1 个 MoE + 1 个长上下文 | 抽检报告 |
| 长稳无泄漏 | 数万请求 × 数小时，显存恒定无碎片上涨 | 监控曲线 |
| 灰度与回滚 | 影子流量 / 小流量灰度 + 一键回滚方案 | 上线方案 |

## 五、测量口径（门禁数值的可信前提）

- 性能数据只信 `msprof` / `msprof op`；禁用 `time.time()`、`torch.npu.Event`、`do_bench` 做性能评价。
- 利用率判据的分母必须是本机校准的 `P_eff` / `BW_eff`（见 [校准台账](../templates/calibration-template.md)），禁止理论峰值；`B* = P_eff / BW_eff`。
- 任务书中的门禁要求与两阶段交付见 [任务书模板](../templates/task-spec-template.md)；红线与阶段路由见 [AGENTS.md](../AGENTS.md)；诊断 SOP 见 [昇腾诊断 SOP](../docs/02-ascend-diagnosis-sop.md)。

## 六、门禁执行流程（探索态 → 验收态）

1. **探索态**：开发分支内快速迭代，同窗 A/B（同并行度 / 同 batch / 同 shape / 同图分桶）验证方向；数据只作参考，**不得入库**。
2. **验收态**：冻结环境（版本快照）+ 门禁在干净容器 / CI 独立执行，输入固定权重 / 数据集；须附从零复现命令与版本；**通过后才允许入库**。
3. 未通过：回 J3 重新归因（或回 J4 回退阶梯），门禁结果归档到 `workspace/<scenario-id>/ledger/` 留痕（不入库）。

> **入库衔接**：验收态通过后，由 Agent 自主沉淀**条目** `cases/<entry-id>.md`（规范见 [docs/05](../docs/05-case-library-and-ledger.md)）并更新 `cases/index.md`。
